Match the attribute, not the word

← Read the article
Text version
  1. Shared table. Translate query words and listing fields into the same typed concepts, such as color: BLUE and productType: SOFA. Each concept lists the words or phrases (aliases) that name it, such as "sofa", "couch" and "loveseat".
  2. Union, not filter. Keep every word match and add listings that satisfy every query concept (AND across concepts, OR across structured field or text alias). Never use an incomplete attribute table as a hard filter.
  3. Score on one scale. Add attribute bonuses on the same 0-to-1 scale as text fit and freshness: +0.05 for a structured field match and +0.025 for a text alias match. A seller field gets twice the weight of a word in the description.
  4. Mentions fool taggers. A word-based tagger reading "fits any blue sofa" assigns color: BLUE and productType: SOFA to a throw pillow. Missing words also cause partial tagging, such as tagging "bathroom vanity knobs" as only VANITY.
  5. Index attributes. Scanning the full catalog at query time slows search down by almost a hundred times. Extract attributes at index time into a concept inverted index and intersect sorted postings lists at query time.

Tags only help as much as the data behind them.
